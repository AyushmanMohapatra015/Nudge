## October19 P4b1/P4b2: controller core and fictional failure verification complete

`scripts/sandbox-rehearsal-controller.cjs` is a reusable operator module, outside application runtime. It exports session creation/reopening only; importing it loads no environment/key/database, launches no process and has no default network delegate or live CLI. Node24.12.0 import and TypeScript checks pass. Application source/configuration/dependencies, ordinary `.env.local` and database remain unchanged.

Implemented controls:

- Dedicated UUID run paths, a private manifest/generated owner token and one-hour deadline. Checks reject external paths and symbolic-link/junction ancestors; database/WAL/SHM paths are checked before supplying child settings. No ordinary DB reset/copy or secret loading occurs in this module.
- Exclusive file lock, versioned manifest and atomic replacement. Stale handles, occupied/interrupted locks and corrupt counters/fixture/approval checksums fail closed. A stale lock is not automatically removed. Checksums detect inconsistent local records, not malicious edits by an operator with write access; this is not a filesystem security sandbox or immutable audit store.
- Setup→AI→review→payment transitions. The caller must confirm the previous app is closed at phase changes. The same DB/token is retained, while an allowlist strips inherited provider secrets and NODE_OPTIONS and selects only that phase's provider settings. The controller alone does not prove a process was stopped: actual owned-process/port verification must be bound by the next runner.
- AI accepts only the canonical instructions, exact fictional title/clauses/request, private/local tool-free request shape and the reviewed Sonnet endpoint. It reuses the one-attempt ledger and reserves before delegation. This is a request limit, not a token/account spending cap. Provider usage capture remains the existing observer's responsibility when the runner is connected.
- Before payment phase, an accepted-scope/accepted-proposal snapshot must match the fixed buyer/agreement, USD300, Elastic provenance, recorded additional/S2 review and unchanged reviewed deliverables, with no existing invoice. A real server snapshot must be supplied by the eventual runner; this module does not authenticate an arbitrary caller-provided object or replace website/server checks.
- Payment transport accepts only the sandbox OAuth path, exact approved create body, bound invoice detail GET and exact send body. It reserves one create and one send before dispatch, including failed responses. OAuth is bounded to4 and detail reads to12 for this helper instance's persisted session. Invalid destination/body/identity cannot dispatch. The returned create identity is bounded/validated and retained; an unknown result does not replenish its slot or enable arbitrary invoice IDs.
- Cleanup callbacks run in tunnel→registration→browser→app→relay order, continuing after failure or a bounded timeout. A timeout requests callback abort and records incomplete cleanup; it does not prove remote cancellation or termination. There is no arbitrary-PID kill/delete command or remote registration operation here. The next runner must bind these callbacks only to resources it owns and independently verify closure/removal.

## Failure and cleanup decisions

| Situation | Action |
| --- | --- |
| AI failure/unknown usage | Consume slot, retain error category, stop. No another-model fallback or paid upgrade. |
| Create/send timeout | Preserve original attempt and ID if returned; inspect the same remote invoice. No new proposal, marker clearing or repeated financial POST. |
| Buyer result uncertain | Inspect authoritative existing invoice first. Leave UI waiting/unknown rather than assert failure or repeat checkout. |
| Delivery unavailable | End bounded observation; label explicit/polling reconciliation accurately. Keep P5 open. |
| Session registration cleanup fails | Keep its private manifest and report cleanup incomplete. Stop public tunnel/relay promptly anyway. Recheck only that registration with a read-only lookup before another exact-ID cleanup attempt. Do not delete all app webhooks. |

In every exit path, stop the session-owned tunnel first if exposure cannot otherwise be bounded. Remove only the registration this run created (verify exact ID and URL); confirm its absence with a list/read, never rely only on an empty local setting. Stop only owned app/relay/browser processes, then verify their loopback ports refuse connections. Retain sanitized operation/usage/status and cleanup outcomes; never swallow an incomplete cleanup as overall success. Session deadlines are operation limits, not payment-link expiries. No restore/reset of ordinary database or environment is part of cleanup.
