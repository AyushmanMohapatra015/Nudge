## Recording and edit instructions

- Use actual working desktop UI. Record each segment with a short pause before and after the action, then trim. Keep clicks, result and narration synchronized. Use subtle cuts and one consistent caption style; no decorative stock footage or unrelated 3D intro.
- Give the scope evidence, USD300 approval, client acceptance and PAID/zero-due result the most screen time. Those are the core proof, not the number of technologies listed.
- Record narration at a conversational pace after a timed read. Aim for about 330–360 words; trim lines if the read exceeds 2:45. Add five seconds of margin below three minutes.
- Use original narration or a permitted synthetic voice with no impersonation. Narration/audio generation capability still needs checking; no audio tool or voice licence has been verified here. Browser recording and final encoding tooling also need checking before promising an exported MP4.
- Use fictional names and scopes. Hide environment files, terminals with credentials, browser password prompts, account emails, API receipts, client tokens and checkout URLs. Inspect the entire exported video frame by frame around browser transitions.
- Show integrated product interfaces only as permitted by the event/vendor terms. Add no sponsor-logo carousel, third-party music, copied template art or other unlicensed assets. Check any branding visible in the actual UI against the applicable permissions before release.
- Distinguish a simulation, replay and live provider response with persistent readable labels. Do not splice a simulated assessment into real checkout and call it one live flow. The final description should state any shortened waits or capture across sessions.
- If a provider fails, stop that take. Preserve its error evidence. Use a clearly labelled previously recorded working segment only if it represents the actual project; a final static mockup or failed demo is not the deliverable.

## Why this story fits the judging criteria

Technology is demonstrated by actual AI evidence and the PayPal invoice/payment lifecycle. Design is demonstrated by the distinct owner and client experiences. Impact is a specific unpaid-extra-work problem; no user counts, revenue impact or time savings are claimed without measurements. Innovation is the clause-to-approval-to-payment connection. Presentation follows one project with one change and one price. Sponsor features support that story rather than turning the video into a tool list. Winning cannot be guaranteed.
