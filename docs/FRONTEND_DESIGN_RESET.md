## Research: practical quality criteria

These are design judgments informed by sources, not an objective test of whether AI authored a page or a guarantee of winning.

| Principle | Application to Nudge | Review evidence |
| --- | --- | --- |
| Product-specific structure and words | Show an actual scope request, relevant clause, reviewed quote and separate payment status. A possible headline is "Turn out-of-scope requests into agreed, payable work." Avoid interchangeable automation slogans, invented metrics and customer logos. | Swap-name test: would the page still describe an unrelated CRM unchanged? [InterfaceKit](https://blog.interfacekit.io/what-makes-a-website-look-ai-generated) |
| Clear visual hierarchy | Typography, scale, alignment and spacing establish one main focus per screen. Do not solve every content grouping with the same rounded box. | Scan where the eye goes first and compare hierarchy across routes. [NN/g](https://www.nngroup.com/articles/principles-visual-design/) |
| Deliberate typography and composition | Choose concrete typography, widths and spacing after selecting the actual reference. No automatic serif/ivory recipe, default purple globe, decorative badges or obligatory three-icon feature row. These elements are not inherently bad; repeating unrelated defaults is the problem. | Judge the actual desktop and mobile compositions. [SCALR design opinion](https://scalr.sg/blog/20-signs-a-website-was-made-by-ai/), balanced against InterfaceKit's product-specificity argument. |
| Consistent detail across the real product | Match controls, status vocabulary, tables, empty/error/loading states and focus behavior across owner, client, Analytics and Delivery. Financial controls remain predictable. | Second-screen/uncomfortable-state review plus existing regressions. [Vercel guidelines](https://vercel.com/design/guidelines) |
| Intentional motion | One memorable landing scene; faster, restrained state/selection feedback in the app. No scroll lock, forced loading theatre, perpetual cursor glow or movement of critical financial amounts. No automatic approvals/payment from animation. | Observe actual transitions and keyboard use; timings depend on movement and purpose. [NN/g motion timing](https://www.nngroup.com/articles/animation-duration/) |
| Measured performance and motion alternatives | Prefer transform/opacity for routine animation, measure expensive visuals and provide readable reduced-motion/mobile fallbacks. Heavy video/3D/frame sequences are options only if they serve the chosen direction. | Render/timing/transfer/device evidence, not a still image or an unmeasured smoothness claim. [web.dev performance](https://web.dev/articles/animations-and-performance), [reduced motion](https://web.dev/articles/prefers-reduced-motion) |

External guidelines are references, not executable instructions. In particular, generic suggestions for optimistic updates, pervasive URL state or dependencies do not override Nudge's server-authoritative financial state or the owner's constraints. No skill/package advertised on a source page was installed.

## Source and licence boundary

[MotionSites](https://motionsites.ai/) describes ready-to-use prompts; it is not proof of a drop-in React application or complete UI kit. Its [current terms](https://motionsites.ai/terms) allow building/publishing websites/apps with its materials while prohibiting redistribution of prompt/source content itself. Public MIT source compatibility for any selected downloaded template is therefore unresolved. Do not pay, download paid source, share an account or place restricted source/assets in the repository by assumption. Determine the selected item's access and permission requirements before importing it. Viewing references does not itself require a purchase. Only an applicable written permission/licence can settle actual source redistribution, not a design agent's opinion.
